This is the canonical command-level authorization matrix for P0-04. Generic role names grant no authority beyond the commands explicitly listed here. `N/A` means the control is intentionally not required. `OPEN` means the value is unsupported and the command must fail closed.

The initial pilot has one School Director authority model. Each School has zero or one active School Director. Temporary Director, Acting Director, substitute Director, and automatic fallback authority are not included. `AUTH-14` and `AUTH-15` remain only as stable denied command IDs; no recipient or subject evidence exists or is required for those excluded capabilities.

## Initial Authorization Bootstrap

- During the sealed one-time Initial Authorization Bootstrap, System Admin may configure any number of initial SESAO Auditor accounts using a unique authenticated application identity, person name, the SESAO Auditor role, and the SESAO Narathiwat organizational scope.
- Application identity binding is a technical requirement, not organizational appointment evidence. Bootstrap requires no appointment-document upload, evidence hash, external verification, or second-person in-application approval.
- Bootstrap configuration grants no School or Audit Assessment access by itself. An Auditor gains Assessment access only through the initial assignment created atomically by `AUTH-26` or a later ESAO Admin assignment under `AUTH-25`.
- The immutable bootstrap configuration version and audit event record the configured person, identity, role, scope, status, System Admin actor, and timestamp. After successful activation, bootstrap is permanently sealed and post-bootstrap changes follow the ordinary Matrix.

## Global Rules

- Every runtime action uses a named authenticated principal; shared accounts are prohibited.
- The initial pilot enables no delegation. Delegated variants remain denied until a later approved Matrix amendment defines grantor, recipient eligibility, capability scope, start/expiry, revocation, invalidation, evidence, and SoD.
- No generic ESAO, platform, emergency, super-admin, or override command exists.
- A Director-required command is denied when the School has no active School Director. No other role inherits or substitutes for School Director authority, and the command's original SoD, evidence, authentication, and reviewer controls still apply.
- Historical authorization and audit evidence remains attributable after later revocation or replacement.
- System Admin is a technical executor only where a row explicitly says so.
- Any number of SESAO Auditor accounts may be configured. An authenticated configured Auditor whose account status is active may execute `AUTH-26`, which atomically creates the Assessment and its initial active assignment. Each Audit Assessment then has at most one active Auditor, and only that assigned Auditor may execute `AUTH-27`, `AUTH-31`, `AUTH-32`, or `AUTH-33` for the exact Assessment, School, audit period, and resolved checklist/policy versions.
- Auditor assignment replacement is atomic: the previous assignment ends before the replacement becomes active, no concurrent active Auditor is permitted, and completion ends executable Auditor authority for that Assessment.
- The five Auditor commands form one end-to-end workflow and require no additional Auditor participant, specialized Auditor role, or extra Auditor approval, verification, or review step.
