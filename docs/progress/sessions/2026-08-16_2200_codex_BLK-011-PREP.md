## Objective

Prepare a structured decision framework to help the Product Owner supply the exact authoritative appointment/organizational evidence type and validation rules required to unblock BLK-011.

---

## Context

BLK-011 blocks P0-04, P0-10, P0-GATE, P1-04, P1-06, and P1-16 because Product Owner Decision 12 (2026-08-15) approved the Substitute School Director Authority model but did not specify:

1. What type of document proves Acting Director Authority appointments
2. What type of document proves Temporary Director Authority appointments
3. What constitutes valid "inability" for Acting authority
4. What constitutes valid "basis that Active/Acting cannot supply holder" for Temporary authority
5. How these documents are stored and validated
6. Renewal and expiry rules

Without these decisions, `AUTH-14` (manage substitute authority) and `AUTH-15` (exercise substitute authority) remain fail-closed even though the governance model is approved.

---

## Work Completed

### 1. Created Decision Framework Document

**File:** `docs/governance/p0-04-blk-011-evidence-decision-framework.md`

The framework provides:

- **Decision A:** Acting Director Authority evidence type options (SESAO order, school-issued with acknowledgment, email from authorized official, external appointment)
- **Decision B:** Temporary Director Authority evidence type options (same categories)
- **Decision C:** Valid inability/unavailability reasons (medical leave, travel, suspension, vacancy, conflict of interest)
- **Decision D:** Valid temporary basis scenarios (no active director, suspended holder, expired acting authority)
- **Decision E:** Evidence storage and verification approach (upload, external reference, hybrid)
- **Decision F:** Expiry and renewal rules (new document required, extension process, maximum duration)

### 2. Recommended Approach

The framework includes a recommended approach for consideration:

```yaml
evidence_type: "SESAO-issued appointment order or memo (digital/email accepted)"
required_fields: "All elements from Decision A/B"
storage: "External reference + optional upload (hybrid)"
inability_basis: "Any documented reason making active Director unable"
temporary_basis: "Explicitly state no active Director or acting unavailable/invalid"
validation: "ESAO Admin verifies completeness; system validates structure/non-overlap"
renewal: "New appointment document required (creates new record/revision)"
duration: "No hard maximum; effective period stated in each appointment"
```

**Rationale:** Balances formality (SESAO authority), flexibility (various inability reasons), and auditability (explicit documentation).

## Notes

The framework is deliberately structured as questions with options rather than requirements, respecting that the Product Owner must make these policy decisions based on:

- Existing SESAO procedures for acting/temporary assignments
- Legal/regulatory requirements for educational institutions
- Appropriate formality level for 17-school pilot
- Balance between strict validation and operational flexibility
- Any past acting/temporary assignment examples

The blocker cannot be cleared until the Product Owner provides these specific inputs — the approved authority model alone is insufficient to implement `AUTH-14`/`AUTH-15` because the system needs to know what evidence to validate and how to validate it.
