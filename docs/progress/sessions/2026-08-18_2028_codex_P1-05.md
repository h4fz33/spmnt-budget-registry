## Work Completed

- Added NextAuth Credentials authentication backed by PostgreSQL through
  Prisma. Credential input is normalized and validated; bcrypt uses cost 10,
  and invalid lookup/input paths compare against a fixed bcrypt hash to avoid
  revealing account existence.
- Added synthetic-identity credential fields and PostgreSQL checks requiring a
  bcrypt cost-10 hash with a password-change timestamp. A database trigger
  requires an authorization-version increase when account status or credentials
  change.
- Added JWT claims, current-account/membership revalidation, authorization-
  version invalidation, and a five-minute fresh-authentication predicate for
  sensitive server paths. Added the server-only session helpers and NextAuth
  route.
- Added live PostgreSQL coverage for active, pending, disabled, unassigned,
  wrong-password, weak-cost, authorization-version, and password-replacement
  paths. No password, hash, activation code, or token value is written to test
  output.
- Added a forward-only migration correcting the shared P1-04 retained-history
  trigger: it now compares polymorphic `OLD`/`NEW` rows through JSONB, so an
  `AuthenticatedIdentity` authorization-version update does not compile a
  School-only `smisCode` reference.
